# API v1 Reference

Base URL: `http://localhost:8000/api/v1`

All endpoints return JSON. Every endpoint except `auth/register` and
`auth/login` requires a Bearer token.

---

## Authentication

Sanctum **personal access tokens**. Send the token on every request:

```
Authorization: Bearer <token>
Accept: application/json
```

| Method | URI | Auth | Description |
| --- | --- | --- | --- |
| POST | `auth/register` | - | Create an account, returns a token |
| POST | `auth/login` | - | Exchange credentials for a token |
| POST | `auth/logout` | Bearer | Revoke the current token |
| POST | `auth/refresh` | Bearer | Issue a new token, revoke the current one |
| GET | `auth/me` | Bearer | Current user with roles and permissions |

`register` and `login` are rate limited to 6 requests/minute.

**Login request**

```json
{ "email": "superadmin@test.com", "password": "1234567890" }
```

**Login response** - `200`

```json
{
  "message": "Login successful",
  "user": { "id": 1, "email": "superadmin@test.com", "roles": ["superadmin"] },
  "token": "1|abcdef..."
}
```

Bad credentials return `422` with the standard validation envelope.

> **Refresh semantics:** Sanctum has no refresh-token concept. `auth/refresh`
> mints a *new* token and revokes the one that authenticated the request, so the
> client must replace its stored token with the response value.

### Seeded accounts

All use password `1234567890`.

| Email | Role | Intended for |
| --- | --- | --- |
| `superadmin@test.com` | superadmin | Everything |
| `admin@test.com` | admin | Everything except force-delete |
| `manager@test.com` | manager | Full catalog, read-only people |
| `editor@test.com` | editor | Create/update catalog, no delete |
| `viewer@test.com` | viewer | Read-only - use this to test 403s |

## Response envelopes

The shapes are consistent across every resource.

**List** - keyed by the plural resource name:

```json
{
  "products": [ { "id": 1, "name": "..." } ],
  "links": {
    "first_page": "...", "last_page": "...",
    "previous_page": null, "next_page": "..."
  },
  "meta": { "current_page": 1, "last_page": 17, "per_page": 15, "total": 250 }
}
```

**Single (show)** - the bare resource object.

**Create / update** - `{ "message": "...", "<resource>": { ... } }`

**Delete / restore** - `{ "message": "..." }`

**Validation error** - `422`:

```json
{ "message": "Validation failed", "errors": { "name": ["The product name field is required."] } }
```

**Authentication error** - `401` `{ "message": "Unauthenticated." }` when the
token is missing, expired or revoked. The frontend should treat this as
"session over" and redirect to sign-in.

**Authorization error** - `403` when the token is valid but lacks the required
permission.

**Server error** - `{ "error": "..." }` with status `500`.

## Query parameters

Supported by **every** index endpoint.

| Param | Example | Notes |
| --- | --- | --- |
| `page` | `?page=2` | |
| `per_page` | `?per_page=25` | Default 15, max 100 |
| `search` | `?search=laptop` | Matches the searchable columns |
| `sort_by` | `?sort_by=price` | Must be in the sortable list |
| `sort_dir` | `?sort_dir=desc` | `asc` (default) or `desc` |
| `filter[field]` | `?filter[brand_id]=3` | Whitelisted fields only |
| `filter[field]` CSV | `?filter[brand_id]=1,2,5` | Becomes a WHERE IN |
| `include` | `?include=tags,images` | Whitelisted eager loads |
| `with_trashed` | `?with_trashed=1` | Include soft-deleted |
| `only_trashed` | `?only_trashed=1` | Only soft-deleted |

Anything not on a whitelist is ignored rather than erroring, so a client can
never sort or filter by an arbitrary column.

Example:

```
GET /api/v1/products?per_page=10&page=2&search=pro&sort_by=price&sort_dir=desc&filter[is_featured]=1&include=tags
```

## Products

| Method | URI | Permission |
| --- | --- | --- |
| GET | `products` | `products.viewAny` |
| POST | `products` | `products.create` |
| GET | `products/{product}` | `products.view` |
| PUT/PATCH | `products/{product}` | `products.update` |
| DELETE | `products/{product}` | `products.delete` |
| PATCH | `products/{product}/restore` | `products.restore` |

- **Searchable:** `name`, `sku`, `barcode`, `short_description`, `description`
- **Sortable:** `id`, `name`, `sku`, `price`, `stock_quantity`, `rating`, `is_featured`, `released_at`, `created_at`
- **Filterable:** `product_category_id`, `brand_id`, `product_status_id`, `unit_of_measure_id`, `is_active`, `is_featured`, `is_digital`, `requires_shipping`, `currency`
- **Includable:** `productCategory`, `brand`, `productStatus`, `unitOfMeasure`, `tags`, `images`, `creator`

### Fields

Deliberately wide, so the UI can exercise every input type.

| Group | Fields |
| --- | --- |
| Identity | `name`*, `slug`, `sku`*, `barcode` |
| Text | `short_description`, `description` |
| Relations | `product_category_id`*, `brand_id`, `product_status_id`*, `unit_of_measure_id` |
| Money | `price`*, `cost_price`, `discount_percentage`, `tax_rate`, `currency` |
| Numbers | `stock_quantity`, `reorder_level`, `weight`, `length`, `width`, `height`, `warranty_months`, `rating` |
| Booleans | `is_active`, `is_featured`, `is_digital`, `requires_shipping` |
| Dates | `released_at`, `available_from`, `expiry_date` |
| JSON | `specifications`, `metadata` (key/value objects) |
| Misc | `color` (hex), `website_url` (url), `contact_email` (email) |
| File | `image` (upload) returned as `image_url` |
| Pivot | `tags` (array of tag ids) |

`*` = required on create.

> **Uploads must be `multipart/form-data`.** `image` accepts jpeg/jpg/png/webp
> up to 2 MB. The response never exposes the raw storage path - only a
> fully-qualified `image_url`.
>
> PHP does not parse multipart bodies on PUT. To update a product *with* a new
> image, POST to `products/{id}` with `_method=PUT` (method spoofing).

### Image gallery

| Method | URI | Permission |
| --- | --- | --- |
| POST | `products/{product}/images` | `products.update` |
| PATCH | `product-images/{product_image}/primary` | `products.update` |
| DELETE | `product-images/{product_image}` | `products.delete` |

Upload sends `images[]` (1-10 files). The first image on a product with no
gallery automatically becomes primary.

## RBAC

| Method | URI | Permission |
| --- | --- | --- |
| GET | `roles` | `roles.viewAny` |
| POST | `roles` | `roles.create` |
| GET | `roles/{role}` | `roles.view` |
| PUT/PATCH | `roles/{role}` | `roles.update` |
| DELETE | `roles/{role}` | `roles.delete` |
| PUT | `roles/{role}/permissions` | `roles.update` |
| GET | `permissions` | `permissions.viewAny` |
| GET | `permissions/grouped` | `permissions.viewAny` |
| GET | `permissions/{permission}` | `permissions.view` |

Roles are user-editable; permissions are **read-only**, because a permission
name only means something if a controller actually checks it.

**Permission naming:** `<resource>.<action>` where action is one of
`viewAny, view, create, update, delete, restore`, plus the
`module.*` sidebar gates (`module.user`, `module.catalog`, `module.settings`).

**Sync a role permissions set** - the write behind the UI matrix:

```json
{ "permissions": ["products.viewAny", "products.view", "products.create"] }
```

`permissions/grouped` returns them pre-grouped for rendering that matrix:

```json
{ "permissions": { "products": ["products.viewAny"], "users": ["users.view"] } }
```

> The `superadmin` role is protected: attempts to rename, delete, or change its
> permissions return `422`. This prevents locking everyone out of RBAC.

Note: roles and permissions live on the `web` guard (spatie default). Routes are
protected with `auth:sanctum`, and `auth.defaults.guard` is deliberately left as
`web` so permission checks resolve against the guard the permissions were
created with. Adding an `api` guard would silently break every check.

## Audit trail

Every write is recorded in `activity_logs`. The endpoints are **read-only by
design** — the log is append-only, and the API deliberately offers no way to
rewrite history.

| Method | URI | Permission |
| --- | --- | --- |
| GET | `v1/activity-logs` | `activity-logs.viewAny` |
| GET | `v1/activity-logs/{id}` | `activity-logs.view` |

Granted to `superadmin` and `admin` only — an audit trail is a security
surface, not general reference data.

### Events

| Event | Trigger |
| --- | --- |
| `created` / `updated` / `deleted` / `restored` | Any audited model |
| `login` / `logout` / `login_failed` / `registered` | `AuthService` |
| `permissions_synced` | `PUT v1/roles/{role}/permissions` |
| `roles_synced` | `PUT v1/users/{user}/roles` |

### Row shape

```json
{
  "id": 3,
  "event": "updated",
  "description": "Product \"Widget\" was updated",
  "subject_type": "App\Models\Product\Product",
  "subject_name": "Product",
  "subject_id": 1,
  "subject_label": "Widget",
  "causer_id": 1,
  "causer_label": "Super Admin",
  "old_values": { "price": "4561.47" },
  "new_values": { "price": "99.99" },
  "ip_address": "127.0.0.1",
  "method": "POST",
  "url": "http://localhost:8000/api/v1/products/1",
  "batch_uuid": "4923792d-…",
  "created_at": "2026-09-04T05:26:22.000000Z"
}
```

- `old_values` / `new_values` contain **only the attributes that changed**, not
  a full snapshot. A save that changes nothing auditable emits no row at all.
- `subject_label` / `causer_label` are snapshotted at event time, so the log
  stays readable after the record or the user is deleted.
- `batch_uuid` groups every row written during one request.
- Passwords and tokens are never logged. `last_login_at` is excluded so a
  sign-in emits `login` rather than `login` plus a noise `updated`.

### Querying

Supports the standard `page` / `per_page` / `search` / `sort_by` / `sort_dir`
contract, plus:

| Filter | Example |
| --- | --- |
| By event | `filter[event]=updated` |
| By actor | `filter[causer_id]=1` |
| One record's history | `filter[subject_type]=App\Models\Product\Product&filter[subject_id]=1` |
| By request | `filter[batch_uuid]=…` |
| Date range | `filter[created_at][from]=2026-09-01&filter[created_at][to]=2026-09-30` |

The `filter[column][from]/[to]` range form is provided by `HasQueryFilters` and
works on any model that declares a `$dateFilterable` whitelist — it is not
specific to the audit log.

### Audit stamps

Every audited table also carries `created_by` / `updated_by` / `deleted_by`
(written by the `HasAudit` trait) as a denormalised shortcut for "who last
touched this?". The activity log remains the authoritative history.

### Extending

To audit a new model: add `use HasAudit;` and
`#[ObservedBy(AuditObserver::class)]`, and give the table the three stamp
columns. Override `auditExclude()` to hide sensitive attributes and
`auditLabel()` to control the display name. Bulk operations that should not
appear as history (seeders, data migrations) call `AuditLogger::disable()`.

## System logs

Read-only access to the application's own log files. There is **no table** behind
this, so it deliberately skips the model/repository layers of the 8-layer
convention — but it returns the same envelope as every other list endpoint.

| Method | URI | Permission |
| --- | --- | --- |
| GET | `v1/system-logs` | `system-logs.viewAny` |
| GET | `v1/system-logs/levels` | `system-logs.viewAny` |

Granted to `superadmin` and `admin` only. Two safeguards, because a log file
leaks more than a table row does:

- **Bounded reads.** Only the newest 2 MB of each file is parsed and at most
  5,000 entries are held, so the endpoint cannot be used to exhaust memory.
- **Redaction.** Values following `password`, `password_confirmation`, `token`,
  `secret`, `api_key` or `Authorization: Bearer` are replaced with
  `[REDACTED]` before the response is built.

```json
{
  "system_logs": [
    {
      "id": 1,
      "logged_at": "2026-09-04 07:19:33",
      "environment": "local",
      "level": "error",
      "message": "Tag creation failed: SQLSTATE[23502] …",
      "context": "#0 /app/vendor/… (stack trace)",
      "file": "laravel.log"
    }
  ],
  "links": { "…": "…" },
  "meta": { "…": "…" }
}
```

Query parameters: `page`, `per_page`, `search` (message and trace),
`filter[level]` (CSV), and `filter[logged_at][from]` / `[to]`.

`id` is synthesised per response — stable enough for a table key, not a
permalink.

### Change own password

`POST v1/auth/password` (`auth:sanctum`, `throttle:6,1`)

```json
{ "current_password": "…", "password": "…", "password_confirmation": "…" }
```

Separate from `PUT v1/users/{id}`, which lets an administrator set a password
without knowing the old one — right for a reset, wrong for self-service.

- The current password is verified against the stored hash. A mismatch returns
  **422** with a `current_password` field error.
- The new password must be at least 8 characters, `confirmed`, and different
  from the current one.
- On success **every other token is revoked** and the current one is kept, so
  the user stays signed in where they are but every other device is signed out.
- Writes `password_changed` / `password_change_failed` to the activity log.
